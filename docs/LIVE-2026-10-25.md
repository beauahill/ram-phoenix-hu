# Live session 2026-10-25 (Crimson + truck) — findings and protocol facts

Everything below was measured on the truck or read out of fresh jadx 1.5.1 decompiles
(`~/jadx-out/<app>/sources` on Crimson; APKs in `apks/`, gitignored). Facts marked
**VERIFY** still need a live confirmation.

## Camera

- **Devices 10, 12 and 14 all deliver the same factory composite.** "Front = 12" and
  "aux overhead = 10" were wrong. There is exactly one picture; view switching is a
  command to the factory module. Front / 360 selector is hidden (`persist.phoenix.cam.selector=1`
  shows it again).
- **OSD touch forwarding:** the stock app sends taps on the picture as
  `MAIN cmd 56 {action, x, y}` (action 0 down / 1 up / 2 move), coordinates scaled to
  800x480 when 360 is active (`com.syu.us FuncSet.sendMcuTouch800x480`). Our activity
  now forwards every touch on the feed the same way; the coordinate space is selectable
  with `setprop persist.phoenix.cam.touch N` (1 = 800x480 default, 2 = 720x480, 3 = raw
  panel px, 4 = 1920x1080, 0 = off). com.syu.ms accepts the cmd (logged with
  `setprop sys.lsec.debug 1`). **VERIFY**: tap the module's own buttons in R and try each N.
  The per-button CAN mapping for this truck lives in the MCU firmware, not in any APK.
- `MAIN update 77 = U_SCREEN_TOUCH_EVENT {down/up, x, y}` is pushed for every panel touch
  whichever app is in front.
- **Parking sensors pinned:** MAIN 14..17 rear, 18..21 front, 0..10 where 10 = clear
  (`IpcRadarSource`). Rear values blink 2/10 at ~2 Hz with a wall behind; the front set
  holds steady. The strip is drawn cluster-style (`ParkingSensorView`).
- **Steering pinned:** MAIN 41 `{position, 168, 84}`, centre 84, swept 23..119.
- Reverse path re-proven: 5 shifts, ~85 ms signal -> camera open, no ghost re-open.
- Debug hook (debuggable builds): `am broadcast -a com.ramphoenix.camera.IPC_CMD --ei module 0 --ei code 56 --eia ints 0,400,440`.

## Vehicle profile correction (late evening)

**The unit is NOT on the LZ RAM profile (6357447).** Broadcasting `com.syu.canbus.enter.air`
opened `com.syu.carinfo.xp.ziyouguang.PAJeepAirControlAct_SP`, the panel for the
`CAR_PA_RAM_*` profiles (FinalCanbus 2740-2746: 13_18 / 20 / 22, H / Low). The exact id is
logged by the launcher at connect (`canbus profile id (DATA[1000]) = ...`). Everything in
the "Climate" section below about `cmd 0 {24, button}` is the LZ protocol and does not
apply; it is kept for the record.

### Climate, PA profile (what actually works)

- Stock panel press = `cmd(7, 6, {1, code})` on ACTION_DOWN, no release packet. Proven live:
  pressing driver seat heat on the stock panel logged `cmd cmdid = 6 [1, 17] from com.syu.canbus`.
- Codes (PAJeepAirControlAct_SP.onTouch): 1 A/C, 2 AUTO, 3 recirc, 4/5 driver temp +/-,
  6/7 fan +/-, 8 face, 9 face+feet, 10 feet, 11 feet+defrost, 12 front defrost, 13 SYNC,
  14 rear defrost, 15 MAX A/C, 16 power, 17/18 seat heat L/R, 20/21 passenger temp +/-,
  22/23 seat vent L/R, 24 heated wheel. Rear zone: `cmd(7, 8, {code})`.
- Read side is the same CANBUS 10..66 set (the PA panel registers 10, 11, 12, 13, 16, 18-21,
  27-32, 37, 40, 53, 62, 65, 66), so the card's state display was already right.

### Camera OSD touch, PA profile

- `CAR_PA_RAM_22_H` is in `PlatForm.isNeedSendTouchCanbus()`, so the stock app forwards
  taps on the picture as **`CANBUS cmd 1029 {touch, x, y}`**, touch 0 = down / 1 = up,
  x, y raw pixels inside its video view (no scaling unless `isSupportSizeSet`). The
  MAIN 56 path only applies when MAIN 81 (360 active) is 1, which it is not here.
- Our camera now defaults to that (`persist.phoenix.cam.touch` 1 = px inside the feed box,
  2 = raw panel px, 3 = 1920x1080, 4 = 1024x600, 5 = the old MAIN 56 800x480). **VERIFY**.

## Climate (RAM 455/LZ profile, superseded above)

- **Root cause of "reads work, writes don't": our release packet.** The RAM handler in
  com.syu.ms (`k0.vr.Z0`) reads `ints[1]` unconditionally; our one-int release `{24}`
  threw ArrayIndexOutOfBounds and the service killed itself (hence the repeated
  `ipc connected` lines). Stock sends `cmd(7, 0, {24, BUTTON})` then `cmd(7, 0, {24, 0})`.
  Fixed; the service now logs both packets and survives. Frame to the MCU:
  `88 55 00 05 E3 C6 02 18 <button> <xor>`. **VERIFY** on a running truck that the
  HVAC changes.
- Button ids 1..24 as documented in CANBUS-IPC.md are confirmed from
  `Air_Activity_All_NewAdd_HP.java:8401-8458`. The RAM panel lives in com.syu.canbus,
  not com.syu.air.
- Read codes confirmed from the frame decoder (`vr.U2`, frame 0x03): 21 fan = low nibble,
  27/28 temps (0 -> -2 LO, 127 -> -1, 255 -> -3 HI), 37 unit, 29..32 seat heat/vent 0..3.

## Vehicle data (what this firmware decodes, and what it does not)

- MAIN 40 outside temperature: `(v & 0xFFFF) - 1000` tenths of a degree, bit 28 = °F
  (live 268437096 -> 64 °F, matched the cluster). Wired (`CanbusVehicleData`).
- CANBUS 1031 speed (raw byte from frame 0x35, units **VERIFY**). Wired.
- CANBUS 0..5 doors: hood, FL, FR, RL, RR, tailgate. Wired (not drawn yet).
- CANBUS 98..171 are **settings bits** (ParkSense, lights, units...), not TPMS/odometer.
- **Not decoded anywhere for this profile:** fuel, coolant, battery, TPMS, odometer, RPM,
  gear, belts. The MCU never emits a frame with them. Options: an OBD-II dongle feed,
  or sniff CANBUS 1052 (every raw box frame is republished there; `setprop log.tag.PhoenixRaw DEBUG`)
  in case the box sends more than the handler parses.

## Audio

- The unit's audio source is **MAIN code 0 "app id"**: 1 radio, 2 BT phone, 3 BT music,
  8 stock music, 10 third-party app, 0 none. `cmd(0, 0, {id})` switches; com.syu.ms moves
  the DSP and takes/releases Android audio focus. `getprop sys.app_id` shows it.
- **Why phone Bluetooth was silent:** nothing selected app id 3. The launcher's media card
  now has BT / RADIO / APPS pills that send the switch; BT play/pause/prev/next are
  BT-module cmds 2/27/0/1; now-playing comes from BT updates 0 title, 1 artist, 26 album,
  13 play state, 28/2 position/duration, 34 A2DP state. **VERIFY** with a paired phone.
- Radio: RADIO-module updates 0 band (65536+n = FM), 1 frequency (FM in 10 kHz units),
  26 station name; cmds 5/6 seek, 0/1 preset next/prev. Card shows "FM 101.9" + name
  when the source is radio. **VERIFY**.
- BT audio is a serial-attached module into the DSP, not Android A2DP; the
  "Bluetooth audio disconnected" media session is a bystander.

## Launcher map card

- Recenter button follows the truck again (long-press opens the Maps app). Layers cycles
  night / satellite / hybrid, 3D tilts with buildings, traffic toggles.
- "Where to?" geocodes addresses with the platform Geocoder and place names via
  Nominatim (OpenStreetMap), drops a pin, GO starts Google Maps turn-by-turn.
  In-card turn-by-turn needs the paid Navigation SDK.
