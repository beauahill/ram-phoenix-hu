# Tire pressures — 2019 RAM 3500 SRW

## Result

Read-only OBD access works through the existing OBDLink MX+, with the truck's
existing gateway configuration. Verified live on 2026-10-26. The factory cluster
shows all four pressures; the driver supplied LF 61, RF 63, LR 72, RR 75 psi.

The earlier claim that pressure data could not be read through the diagnostic
port was premature. The client assumed every 11-bit reply ID was `request + 8`.
This endpoint receives on **0x740** and replies on **0x4C0**, and its longer replies
require custom ISO-TP flow control. A `22 F190` discovery sweep with an assumed
reply ID cannot establish that the gateway blocks a module or its pressure reads.

## Adapter setup

Standard 11-bit CAN at 500 kbit/s, normal ISO-TP formatting:

```
ATSP6
ATH0
ATCAF1
ATCFC1
ATSH740
ATCRA4C0
ATFCSH740
ATFCSD300000
ATFCSM1
```

Header/data must precede `ATFCSM1`. Restore `ATFCSM0` before returning to the
standard engine routes. The app now supports `TX/RX` routes such as `740/4C0` and
validates the adapter's acknowledgement instead of assuming its setup succeeded.

## Requests and live validation

| Request | Meaning on this truck | Raw pressure | kPa | psi before display | Cluster |
|---|---|---:|---:|---:|---:|
| `22 A0F1` | front left | `1070` | 420.8 | 61.0319 | 61 |
| `22 A0F2` | front right | `1130` | 440.0 | 63.8166 | 63 |
| `22 A0F3` | rear left | `13A9` | 503.3 | 72.9975 | 72 |
| `22 A0F4` | rear right | `1469` | 522.5 | 75.7822 | 75 |

Pressure = unsigned big-endian first two data bytes / 10 kPa, then multiply by
0.145037738 for psi. `FFFF` means unavailable. Decimal values are retained in the
data model; whole-psi labels truncate, matching this live cluster comparison.
Validate the display behavior again when pressures change.

**Rear order is important:** the older 2017 public example labels A0F3/A0F4 as
RR/RL. On this 2019 SRW, the live values map A0F3 to LR and A0F4 to RR. Do not copy
the older mapping into this truck's profile.

`22 A0A5 -> 62 A0 A5 0F` marked all four available. The client requires all four
validity bits before publishing a snapshot; individual invalid-bit assignments
have not been physically tested.

`22 A0A1` also answered. Its combined summary (labeled altitude-compensated by the
public definition) returned LF 60, RF 63, RR 75, LR 72. The driver confirmed LF
still read 61 on the cluster. The app therefore uses the individual pressure
records rather than adding a correction to the summary value.

ELM's multi-frame response includes a length and numbered lines. Example captured
from the truck for LF:

```
00C
0:62A0F1107000
1:003E605D0E0E00
```

Strip line indexes, respect the declared application length and discard frame
padding before extracting data. Negative, truncated and out-of-sequence replies
must not be interpreted as pressure.

## Launcher implementation

- `RamHdTpms` contains this truck's verified four-wheel profile.
- `ObdRoute` configures actual response IDs and flow control, and restores the
  standard settings for existing coolant/transmission/oil reads.
- `ObdPayload` validates/assembles formatted multi-frame replies.
- The existing single OBD worker polls pressures every 15 seconds. Readings
  expire after 45 seconds without a successful update and clear on disconnect.
- `CanbusVehicleData.tirePsi()` now reads the OBD snapshot for the vehicle card.
- Set `persist.phoenix.obd.tpms=0` to disable these requests; `1` enables them.
- This profile is for the verified 2019 3500 SRW. DRW/six-wheel and other model
  years require their own mapping and validation.
